Ask this now

Section A · Frontier 3: competing body edits

Question: Should reads return a description-specific monotonic revision that every description set|clear request must supply, so only an intervening body change causes a mismatch?

Recommendation: Yes. Compare inside the serialized mutation turn; mismatch leaves the body unchanged and returns the current description revision; success returns the incremented revision.

Why not the aggregate event position?

Status, links, attachments, and future comments would cause unrelated conflicts. A body-specific revision protects the resource the user is actually editing.

Evidence and constraints

Why the sequence matters

Current-state evidence
The public WorkItem DTO exposes no revision. The actor persists an ordered event list, but its aggregate position changes for status, links, attachments, and future comments as well as body mutations. The existing server update loop also emits separate commands and omits empty strings.
Product V1 guardrails
Accepted mutations must survive restart and replay. Competing supported callers must receive correct revision behavior. Validation, revision mismatch, and persistence failure must not publish partial success. CLI, HTTP API, SDK, OpenAPI, generated clients, docs, and tests must agree.
Provisional language
  • Work-item body: current replaceable Markdown description.
  • Comment: chronological entry with identity, creator, and timestamp.
  • Correction: later comment preserving the original record.
  • Activity entry: read-only projection, never a second write model.
  • Attached evidence: prompt, summary, or review content governed by #810.
  • Description revision: monotonic compare-before-write value changed only by body set or clear.
Candidate tracer

Read a work item and description revision; set or clear using that expected revision; observe one durable transition and incremented revision; reject a competing older revision unchanged; prove non-empty input converges while empty set input directs users to clear.

This tracer stays provisional until DEC-007 closes.
