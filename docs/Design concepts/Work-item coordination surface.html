Settled DEC-008 contract

Attachments are one public resource

Accepted decision: Remove WorkItemDto.Notes and expose work-item attachments without a public semantic type, replacement role label, type bucket, or type-based latest lookup.

Boundary: Keep the internal ArtifactType union, generic Artifact API, persisted metadata, and producer-specific behavior unchanged until a separate internal design pass.

Public behavior

Callers add one attachment without --type, list a single collection, and identify one attachment by artifact ID. The existing owned-attachment deletion lifecycle remains.

Decision map

What is settled, recommended, and open

DEC-001 · accepted

#810 baseline

Keep delivered status and owned-attachment contracts without compatibility aliases.

DEC-002 · accepted

Coordination outcome

Work items carry evolving intent, collaboration, and progress now handled through GitHub.

DEC-003 · accepted

Replies and threads

Use one chronological stream. Responses are later comments; defer replies and resolved discussion state.

DEC-004 · accepted

Direct comment editing

Comments are immutable. Corrections are new comments with their own identity, creator, and timestamp plus an explicit reference to the original.

DEC-005 · accepted

Body meaning

Description is one replaceable Markdown body containing current task intent, purpose, and acceptance context; Title remains separate.

DEC-011 · accepted

Long-text input

Accept exactly one of --text, --file, or --stdin; defer interactive editing and patch input.

DEC-006 · accepted

Set and clear

Use workitem description set|clear. Require exactly one non-empty --text, --file, or --stdin source. Read file or standard input completely without text normalization, reject empty, unreadable, absent, and multiple sources before a request, and direct intentional removal to clear.

DEC-007 · accepted

Competing description writes

Append-order last-write-wins. The serialized actor accepts descriptions in order; the last appended description is current. No public or persisted revision, comparison value, history, or previous-version link is added.

DEC-013 · accepted

Usage accounting boundary

Section A keeps Utf8ByteLength as an internal integrity fact but publishes no repository-storage usage fact. Accounting is deferred to #829 under Operations epic #554.

DEC-008 · accepted

Notes and attachment vocabulary

Remove WorkItemDto.Notes. Reserve “comment” for collaboration and expose one untyped work-item attachment resource. Do not add a replacement role label; defer internal ArtifactType redesign.

DEC-012 · open · partially accepted

Comment lifecycle

Comments have no ordinary delete or hide operation. Administrative moderation is deferred to standalone issue #876 outside this epic. Define identity, ordering, correction, retry, and replay without expanding Section B into moderation policy.

DEC-010 · open

Progress projection

One read-only timeline combining work-item changes and comments.

DEC-009 · open

List and search scope

Repository list first; then title/body search. Defer organization and comment-content search.

Evidence and constraints

Why the sequence matters

Current-state evidence
The actor persists ordered WorkItem events. #826 replaces description strings with immutable Description and TextContent references, #827 adds explicit clear as a new immutable Description without TextContent, and #828 adds exact text, file, and standard-input sources. The internal projection retains only the current reference and the public read boundary hydrates current UTF-8 text. Grace has a repository-storage fact contract and ingestion path but no production producer; #825 therefore claims no accounting behavior.
Product V1 guardrails
Accepted mutations survive restart and replay. Competing supported description writes append in serialized actor order, and the last accepted append is current. Validation and persistence failure publish no partial success; uncertain retries retain their immutable object. CLI, HTTP API, SDK, OpenAPI, generated clients, docs, and tests agree.
Provisional language
  • Work-item body: current replaceable Markdown description.
  • Comment: chronological entry with identity, creator, and timestamp.
  • Correction: later comment preserving the original record.
  • Comment moderation: future privileged capability tracked in #876 outside this epic.
  • Activity entry: read-only projection, never a second write model.
  • Attachment: supporting content owned by a work item, with no Grace-prescribed public semantic type.
  • Append order: accepted serialized description order; the final append is current.
#826/#827/#828 description slices

Create or resolve a work item; set Markdown from text, file, or standard input; hydrate the current description without storage facts; clear with a new empty immutable Description that writes no Blob; set again and observe the last accepted append. Prior content remains retained without a public history.

These slices implement settled DEC-006, DEC-007, and DEC-013 without adding public history, cross-provider storage, or retained-content accounting.
